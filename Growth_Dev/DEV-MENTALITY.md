# MY META THEORY OF DEV GODHOOD

### I have decided upon a core "schedule", did/didnt and new concept/improvement (so that is very fluid with an vague boundary)

## "WE GOIN BLIND BBY" 
- Always create specific per chain files e.g file.html, file.js, file.css
- Idea is so that every future new concept i learn has a per chain structure; i.e per html,css,and js file (then like specific connected files like lua.lua)

## "OH THAT SEEMS FAMILAR" 
- OCCASIONALY DO PATTERN RECOGNITION, IF SOMETHING WORKS FOR MORE THAN ONE THING rework and MERGE if POSSIBLE
- Idea is so that one can clean up code every so often, and check if it can be improved

## "RECURSIVE REFORGING" 
- ONCE PER WEEK FOR EXAMPLE overview recent work, ONCE PER MONTH SCAN OVER EVERYTHING, and rework and merge if needed
- Idea is every week to mainly push changes to github, and also check work past week, same for monthly but everything in project area

## "GLOBAL IS GOOD" 
- DONT BE COMPLETELY AN IDIOT, IF SOMETHING IS VERY OFTEN, MAKE IT MORE GLOBAL, CONNECT TO MAIN (css or js) 
- Idea is literal, if something is used very often, make it global, and if it is used less, make it local (or well specifically per chain structure)

## "GUT GLOBAL" 
- IF GLOBAL "NODES" are too bloated GUT THEM INTO SPLIT FILES e.g split-1, split-2... and import back to MAIN
- Idea is so that if a global node is too big, split it into smaller chunks, and import back to main, quite simple

## "IS GLOBAL GOOD" 
- CONFIRM EVERYTHING THAT USES GLOBAL NODES USE AND NEED SUCH. ELSE GO BACK TO STONE-AGE.
- Idea is so that if something is used very often, make it global, and if it is used less, make it local (or well specifically per chain structure, again)
